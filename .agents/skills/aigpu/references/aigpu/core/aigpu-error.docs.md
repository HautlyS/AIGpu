# AIGpuError

`AIGpuError` is the structured error base class used by aigpu. Use it when you need stable machine-readable `code`, `severity`, optional `fix`, `where`, and `cause` fields instead of parsing error messages.

## Import

```ts
import { AIGpuError, ValidationError } from "aigpu/core";
```

## Signature

```ts
type AIGpuErrorSeverity = "error" | "warning" | "info";

interface AIGpuErrorData {
  readonly code: string;
  readonly message: string;
  readonly severity?: AIGpuErrorSeverity;
  readonly fix?: string;
  readonly where?: string;
  readonly cause?: unknown;
}

declare class AIGpuError extends Error {
  readonly code: string;
  readonly severity: AIGpuErrorSeverity;
  readonly fix?: string;
  readonly where?: string;
  readonly cause?: unknown;
  constructor(data: AIGpuErrorData);
}

declare class ValidationError extends AIGpuError {
  constructor(data: Omit<AIGpuErrorData, "severity">);
}
```

## Parameters

### `new AIGpuError(data)`

| Param | Type | Required | Default | Notes |
|---|---|---:|---|---|
| data.code | `string` | ✔ | — | Stable machine-readable code. Core validation sites use `AIGPU-CORE-*` codes. |
| data.message | `string` | ✔ | — | Human-readable message passed to `Error`. |
| data.severity | `"error" \| "warning" \| "info"` | ✖ | `"error"` | Stored as `.severity`; omitted data becomes an error. |
| data.fix | `string` | ✖ | `undefined` | Optional remediation text. |
| data.where | `string` | ✖ | `undefined` | Optional source/context label such as `"Device.createBuffer"`. |
| data.cause | `unknown` | ✖ | `undefined` | Forwarded to `Error` via `{ cause }` and stored as `.cause`. |

### `new ValidationError(data)`

| Param | Type | Required | Default | Notes |
|---|---|---:|---|---|
| data.code | `string` | ✔ | — | Stable machine-readable validation code. |
| data.message | `string` | ✔ | — | Human-readable validation message. |
| data.fix | `string` | ✖ | `undefined` | Optional remediation text. |
| data.where | `string` | ✖ | `undefined` | Optional source/context label. |
| data.cause | `unknown` | ✖ | `undefined` | Optional original error or validation detail. |

**Returns:**

- `new AIGpuError(data)` returns an `Error` instance with `.name === "AIGpuError"`, `.code`, `.severity`, optional `.fix`, optional `.where`, and optional `.cause`.
- `new ValidationError(data)` returns a `AIGpuError` subclass with `.name === "ValidationError"` and `.severity === "error"`.

**Throws:** Constructors do not throw aigpu errors. They can only throw if the JavaScript runtime cannot construct `Error` or assign fields.

## Examples

```ts
import { AIGpuError } from "aigpu/core";

const error = new AIGpuError({
  code: "AIGPU-CORE-INVALID-USAGE",
  message: "Buffer size must be greater than zero.",
  severity: "error",
  where: "Device.createBuffer",
  fix: "Pass a positive byte length.",
});

console.log(error.name, error.code, error.severity, error.where);
```

```ts
import { ValidationError } from "aigpu/core";

function requirePositive(value: number): void {
  if (value <= 0) {
    throw new ValidationError({
      code: "AIGPU-CORE-INVALID-USAGE",
      message: "Expected a positive value.",
      where: "example.requirePositive",
    });
  }
}

try {
  requirePositive(0);
} catch (error) {
  if (error instanceof ValidationError) {
    console.log(error.code); // "AIGPU-CORE-INVALID-USAGE"
  }
}
```

## Notes

- Match on `.code`, not `.message`. Messages can become more descriptive; codes are the stable contract.
- `ValidationError` forces severity to `"error"`; use `AIGpuError` directly for `"warning"` or `"info"` severities.
- Core currently emits these `AIGPU-CORE-*` codes from core layer (`aigpu/core`) code paths: `AIGPU-CORE-INVALID-USAGE`, `AIGPU-CORE-VALIDATION`, `AIGPU-CORE-EXTERNAL-TEXTURE`, `AIGPU-CORE-TEXTURE-RESIZE-LOCKED`, `AIGPU-CORE-TEXTURE-DESTROYED`, `AIGPU-CORE-UNSUPPORTED-FORMAT`, `AIGPU-CORE-BIND-GROUP-LAYOUT-REQUIRED`, `AIGPU-CORE-SAMPLER-ANISOTROPY-FILTERS`, `AIGPU-CORE-BINDING-INVALID`, and `AIGPU-CORE-VISIBILITY-INVALID`.
- Native WebGPU errors are converted to `AIGPU-CORE-VALIDATION` only by `Device.popErrorScope()`; other native calls may still throw native errors directly.
- **See also:** `Device`, `Buffer`, `Texture`, `bind`, `AIGpuAdapter`.
