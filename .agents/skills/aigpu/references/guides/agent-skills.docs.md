# AIGpu Agent Skills and plugins

AIGpu ships a portable `aigpu-agent-toolkit` skill for coding agents. The skill teaches an agent how to choose the smallest AIGpu entrypoint, preserve framework independence, connect serializable state, build accessible UI, validate WebGPU/WGSL code, and run the project gates. It contains no provider credentials, hosted runtime, telemetry, or hidden network dependency.

## Install from a published repository

Install the skill for the common coding agents:

```sh
npx -y skills add hautlys/AIGpu \
  --skill aigpu-agent-toolkit \
  -a claude-code \
  -a opencode \
  -a codex \
  -y
```

Install for every compatible agent detected by the installed CLI:

```sh
npx -y skills add hautlys/AIGpu \
  --skill aigpu-agent-toolkit \
  --agent '*' \
  -y
```

Use `-g` for a user-wide installation and `--copy` when symlinks are unavailable or undesirable:

```sh
npx -y skills add hautlys/AIGpu \
  --skill aigpu-agent-toolkit \
  --agent '*' \
  --global \
  --copy \
  -y
```

The exact target list may grow with the CLI. The plugin metadata advertises Claude Code, OpenCode, Codex, Cursor, GitHub Copilot, Cline, and Gemini CLI, while `--agent '*'` delegates final compatibility selection to the installed CLI.

## Install from a local checkout

```sh
npx -y skills add ./ --list
npx -y skills add ./ --skill aigpu-agent-toolkit -a claude-code -a opencode -a codex --copy -y
```

The repository-local installer is convenient for contributors:

```sh
node scripts/install-agent-skills.mjs
node scripts/install-agent-skills.mjs --agent=claude-code --agent=opencode --agent=codex
node scripts/install-agent-skills.mjs --all --global
```

The installer delegates to the open Agent Skills CLI. It does not install an AI provider, modify application dependencies, or connect to a hosted AIGpu service.

## What the skill teaches

The skill covers:

- `agentAnimation()` for direct GPU animation.
- `mountAgentCanvas()` for HTML and custom lifecycles.
- `@aigpu/react`, `@aigpu/vue`, and `@aigpu/svelte` as optional adapters.
- `aigpu/tools` stores, registries, event recording, and replay.
- Accessible status cards, reduced motion, SSR, hydration, cleanup, and device ownership.
- WGSL authoring, reflection, diagnostics, performance budgets, and deterministic tests.
- Local CLI, offline documentation, examples, and MCP stdio.
- Roadmap-oriented implementation: contract first, example second, test third, docs and budgets last.


## Recommended agent workflow

1. Ask the agent to inspect the relevant package and load only the required reference document.
2. Define a plain event or patch contract before choosing a framework adapter.
3. Implement the framework-free layer and deterministic tests first.
4. Add a thin adapter or example only when the lifecycle differs.
5. Keep accessibility and reduced-motion behavior in the example, not as an afterthought.
6. Run the skill validator, typecheck, tests, docs generation, and bundle check.
7. Review generated skill changes and commit them together with the source docs.

## Troubleshooting

If an agent cannot discover the skill, run `npx -y skills add ./ --list` and confirm `aigpu-agent-toolkit` appears. If the project has no agent directory yet, use `--copy` or create the directory through the CLI rather than manually guessing an agent-specific path. If symlinks are unsupported, use `--copy`. If a project-local skill should be available everywhere, repeat the installation with `--global`.

The skill is instruction-only. Runtime functionality still comes from the AIGpu packages and the application remains responsible for model permissions, data retention, transport security, and user consent.
